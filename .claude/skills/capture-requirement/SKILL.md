# Capture Requirement

Skill นี้เป็น workflow มาตรฐานสำหรับแปลงความต้องการดิบที่ผู้ใช้เล่ามา (ข้อความอิสระ,
บันทึกการประชุม, รายการ feature ที่อยากได้ ฯลฯ) ให้กลายเป็นเอกสาร Requirement
Specification ที่เป็นทางการของโปรเจกต์นี้ พร้อมอัปเดต backlog และ log ให้ครบ
ตามกฎใน `CLAUDE.md`

## เมื่อถูกเรียกใช้

1. **รับ input**: ถ้าผู้ใช้ยังไม่ได้แนบความต้องการดิบมาพร้อม args ให้ถามผู้ใช้ตรงๆ ว่า
   ต้องการบันทึกความต้องการอะไร (รับเป็นข้อความอิสระได้เลย ไม่ต้องมีรูปแบบตายตัว)

2. **ส่งต่อให้ subagent `requirement-writer`**: เรียกผ่าน Agent tool
   (`subagent_type: requirement-writer`, รันแบบ foreground คือ `run_in_background: false`
   เพราะ subagent นี้ต้องถามคำถามผู้ใช้แบบโต้ตอบผ่าน AskUserQuestion ระหว่างทาง)
   โดย prompt ที่ส่งต้องมี:
   - ข้อความ requirement ดิบทั้งหมดที่ผู้ใช้ให้มา (verbatim อย่าสรุปย่อเอง เดี๋ยว agent จะตีความเอง)
   - เอกสารหรือหัวข้อใดๆ ที่ผู้ใช้อ้างถึงในบทสนทนา (ถ้ามี) พร้อม path ถ้ารู้
   - บริบทว่านี่คือ session สนทนากับผู้ใช้จริง คำถามที่ subagent ถามจะไปถึงผู้ใช้ทันที
     ไม่ใช่ mock/สมมติคำตอบเอง

3. **รอผลลัพธ์**: เพราะรันแบบ foreground เทิร์นนี้จะได้รับผลลัพธ์ก่อนตอบผู้ใช้ต่อ
   ระหว่างที่ subagent ถามคำถามผู้ใช้ ให้ปล่อยให้ subagent จัดการเอง อย่าตอบแทนผู้ใช้

4. **สรุปให้ผู้ใช้ทราบ**: หลัง subagent ทำงานเสร็จ ให้สรุปสั้นๆ ว่า
   - สร้าง/แก้ไขเอกสารอะไรที่ path ไหน
   - เพิ่มรหัส FR-xx/NFR-xx อะไรบ้าง
   - อัปเดต backlog.md และ log แล้ว
   - มีจุดใดที่ subagent รายงานว่ายังไม่ชัดเจน ต้องให้ผู้ใช้ตัดสินใจเพิ่มเติมหรือไม่

## ข้อควรระวัง

- ห้ามข้ามการเรียก subagent แล้วเขียนเอกสารเองตรงๆ ในเทรดหลัก — subagent คือแหล่งความจริง
  เดียวของกฎการตั้งชื่อไฟล์ เลขรัน และการจัดรหัส FR/NFR ไม่ให้ชนกัน การเขียนเองเสี่ยงข้อมูล
  ไม่สอดคล้องกับเอกสารที่มีอยู่แล้ว
- ถ้าผู้ใช้ส่ง requirement ดิบมาหลายเรื่องไม่เกี่ยวข้องกันในคำขอเดียว ให้ใช้ AskUserQuestion ถามก่อน
  โดยเสนออย่างน้อย 3 ตัวเลือก: (1) แยกเป็นหลายเอกสาร เอกสารละเรื่อง, (2) รวมเป็นเอกสารเดียว,
  หรือ (3) แยกเป็นหลายเอกสารแต่เชื่อมโยงกันด้วย `[[wikilink]]` เพราะเกี่ยวข้องกันบางส่วน — แนะนำ
  ตัวเลือก (1) เป็นค่าเริ่มต้น (ต่อท้าย label ด้วย "(แนะนำ)") ถ้าหัวข้อไม่เกี่ยวข้องกันจริงๆ เพราะ
  ทำให้แต่ละเอกสารยังคุมรหัส FR/NFR และประวัติแก้ไขของตัวเองได้ชัดเจน แล้วส่งให้ subagent ทีละเรื่อง
  หรือรวมกันตามที่ผู้ใช้เลือก
