## FR-24 (ขยายขอบเขต 2026-10-17): ปฏิเสธคำตัดสินเมื่อไม่ได้ถือล็อกที่ใช้ได้
- `r02-review.html`: แถบจำลอง 3 สาเหตุ (ล็อกหมดอายุ / ถูกอาจารย์-Admin ปลดมือ FR-21 / ผู้ตรวจอื่นล็อกต่อ FR-18) เมื่อกดอนุมัติหรือปฏิเสธจะเห็นข้อความตามสาเหตุ ผลเหมือนกันทุกกรณี: ไม่บันทึกเป็นคำตัดสิน ข้อความยังรออนุมัติ ไม่ปรากฏในห้องรวม (NFR-04)
- `r03-audit.html`: แถว "คำตัดสินถูกปฏิเสธ" ครบ 3 สาเหตุ (ตัวอย่าง M-0005, M-0002, M-0006)
- assumption ที่ spec ยังไม่ยืนยัน: การบันทึก "การปฏิเสธคำตัดสิน" เป็นเหตุการณ์แยกใน audit trail; ยังเปิดคำถามว่าควรแจ้งผู้ตรวจที่ล็อกต่ออยู่ด้วยหรือไม่ (prototype แจ้งเฉพาะผู้ที่ถูกปฏิเสธ)

## จุดที่เน้นตาม NFR / หลักการออกแบบ
- สีสถานะไม่ใช้สีอย่างเดียว: badge/alert มีไอคอน (สร้างด้วย CSS) + ข้อความเสมอ (DESIGN §9)
- ปุ่มหลัก 1 ปุ่มต่อหน้า ปุ่ม "ปฏิเสธ" ใช้ Danger และต้องกรอกเหตุผล (FR-15) ปุ่มอนุมัติปิดใช้จนกว่าจะระบุเชิงลบ/ไม่เชิงลบ (FR-12)
- เมนูแยกตามบทบาท เมนูที่ไม่มีสิทธิ์ไม่แสดง (NFR-01) ผู้อ่านห้องรวมไม่เห็นข้อความรออนุมัติ/ถูกปฏิเสธ (NFR-04)
- ตัวจำลอง (แถบเส้นประ "เฉพาะ prototype") ใช้สลับสถานะ เช่น ระดับความเสี่ยง, ซิงก์ล้มเหลว, ล็อกหมดอายุ, สิทธิ์ผู้ส่ง, นโยบายแสดงชื่อ
- responsive: เมนูข้างยุบเป็น drawer ที่ <1024px, ตารางเลื่อนแนวนอนบนจอแคบ, ปุ่ม/พื้นที่กด >= 44px บนมือถือ

## ค่าที่ spec ยังไม่กำหนด (ใช้ placeholder ติดป้าย "ตัวอย่าง")
- T_unlock (เวลาปลดล็อกอัตโนมัติ) ตัวอย่าง 30 นาที; ความถี่ซิงก์; ช่องทางแจ้ง admin (ตัวอย่าง in-app); ค่า threshold; การแปลงจำนวนเงื่อนไขเป็นระดับ (1 = เฝ้าระวัง, >=2 = เสี่ยงสูง ซึ่งเป็นสมมติของ prototype)
- นิยาม "ผ่านเกณฑ์" ของผู้ส่ง, การแจ้งผู้ส่งเมื่ออนุมัติ, นโยบายแสดงชื่อผู้ส่ง (NFR-06), ครูได้รับแจ้งเตือนหรือไม่ (FR-07)
- ปีในวันที่: ใช้ ค.ศ. ชั่วคราว (DESIGN §12 ข้อ 4 ยังไม่กำหนด พ.ศ./ค.ศ.)

## ข้อจำกัด
- ยังไม่ได้ตรวจด้วยเบราว์เซอร์จริง ตรวจจากการอ่านไฟล์เท่านั้น
- proto-bar/header/sidebar สร้างด้วย JavaScript (`app.js`) ถ้าปิด JS จะเห็นเฉพาะเนื้อหาหลัก
- หน้า r01-r03 แสดงเมนูฝั่งอาจารย์ (อาจารย์และ Admin สิทธิ์เท่ากัน) ไม่มีตัวสลับบทบาทในหน้าเหล่านี้
- ยังไม่ได้วัด contrast ของคู่สีสถานะด้วยเครื่องมือ (ตาม DESIGN §9)
- ไม่มีกราฟ/ชาร์ต จึงไม่ได้ใช้ skill dataviz; แสดงเป็นตารางและป้ายสถานะแทน
