# Feature List

จัดกลุ่ม FR/NFR จาก [[../01-requirements/backlog|Backlog]] เป็นฟีเจอร์ระดับผู้ใช้ (ที่มา: [[../01-requirements/01-spec/20261014-01-student-risk-alert|REQ-01 ติดตามและแจ้งเตือนความเสี่ยง]], [[../01-requirements/01-spec/20261014-02-peer-advice-chat|REQ-02 ช่องแชทแนะนำแนวทางการเรียน]], [[../01-requirements/01-spec/20261016-01-sync-failure-handling|REQ-03 ซิงก์ล้มเหลว]], [[../01-requirements/01-spec/20261016-02-peer-chat-recipients-lock-resubmit|REQ-04 ห้องรวม ปลดล็อกผู้ตรวจ ส่งใหม่หลังถูกปฏิเสธ]] และ [[../01-requirements/01-spec/20261016-03-first-sync-failure-and-expired-lock-decision|REQ-05 ซิงก์ครั้งแรกล้มเหลว และคำตัดสินหลังล็อกหมดอายุ]])

## 1. เชื่อมต่อและซิงก์ข้อมูลจากระบบเดิม
ดึงข้อมูลเกรด/ผลการเรียน การเข้าเรียน และการส่งงานจากระบบเดิมผ่าน API ความถี่การซิงก์ยังไม่กำหนด
- รหัส: [[20261014-01-student-risk-alert|FR-01]], [[20261014-01-student-risk-alert|NFR-03]]
- บทบาทผู้ใช้: ผู้ดูแลระบบ (ระบบทำงานเอง)
- ระดับความสำคัญ (MoSCoW): Must have

## 2. วิเคราะห์แนวโน้มและประเมินความเสี่ยง
คำนวณแนวโน้มผลการเรียนจากข้อมูลย้อนหลัง และประเมินความเสี่ยงจาก 4 ตัวแปรด้วยกฎ threshold
- รหัส: [[20261014-01-student-risk-alert|FR-02]], [[20261014-01-student-risk-alert|FR-03]]
- บทบาทผู้ใช้: ผู้เรียน, ครู/อาจารย์ที่ปรึกษา
- ระดับความสำคัญ (MoSCoW): Must have

## 3. ตั้งค่า threshold ความเสี่ยง
ผู้ดูแลระบบปรับค่า threshold การประเมินรอบถัดไปใช้ค่าใหม่
- รหัส: [[20261014-01-student-risk-alert|FR-08]]
- บทบาทผู้ใช้: ผู้ดูแลระบบ
- ระดับความสำคัญ (MoSCoW): Must have

## 4. แจ้งเตือนความเสี่ยงพร้อมเหตุผล
แจ้งผู้เรียนทาง in-app และอีเมลเมื่อเข้าเงื่อนไขเสี่ยง และบอกเหตุผลว่าเข้าเงื่อนไขใด
- รหัส: [[20261014-01-student-risk-alert|FR-04]], [[20261014-01-student-risk-alert|NFR-02]]
- บทบาทผู้ใช้: ผู้เรียน
- ระดับความสำคัญ (MoSCoW): Must have

## 5. คำแนะนำการเรียนเฉพาะบุคคล
สร้างคำแนะนำจากข้อมูลย้อนหลังของผู้เรียนแต่ละคน (ผู้เรียนใหม่ใช้กฎพื้นฐาน)
- รหัส: [[20261014-01-student-risk-alert|FR-05]]
- บทบาทผู้ใช้: ผู้เรียน
- ระดับความสำคัญ (MoSCoW): Must have

## 6. แดชบอร์ดสถานการณ์การเรียนของผู้เรียน
แสดงสถานการณ์การเรียนหลายตัวแปรของผู้เรียนในหน้าเดียว
- รหัส: [[20261014-01-student-risk-alert|FR-06]]
- บทบาทผู้ใช้: ผู้เรียน
- ระดับความสำคัญ (MoSCoW): Should have

## 7. มุมมองครู/อาจารย์ที่ปรึกษา
ดูสถานการณ์และการแจ้งเตือนของผู้เรียนในความดูแล (ยังไม่กำหนดว่าครูได้รับแจ้งเตือนด้วยหรือไม่)
- รหัส: [[20261014-01-student-risk-alert|FR-07]]
- บทบาทผู้ใช้: ครู/อาจารย์ที่ปรึกษา
- ระดับความสำคัญ (MoSCoW): Should have

## 8. ประวัติการแจ้งเตือนและคำแนะนำ
เก็บและเปิดดูประวัติการแจ้งเตือนและคำแนะนำย้อนหลัง
- รหัส: [[20261014-01-student-risk-alert|FR-09]]
- บทบาทผู้ใช้: ผู้เรียน, ครู/อาจารย์ที่ปรึกษา
- ระดับความสำคัญ (MoSCoW): Could have

## 9. ความเป็นส่วนตัวและสิทธิ์การมองเห็นข้อมูลการเรียน
ข้อมูลผลการเรียนเป็นข้อมูลส่วนบุคคล จำกัดการมองเห็นตามบทบาท (ต้องยืนยันนโยบาย PDPA)
- รหัส: [[20261014-01-student-risk-alert|NFR-01]]
- บทบาทผู้ใช้: ผู้เรียน, ครู/อาจารย์ที่ปรึกษา
- ระดับความสำคัญ (MoSCoW): Must have

## 10. ส่งข้อความแนะนำแนวทางการเรียน
ช่องแชทให้นักศึกษาผู้ผ่านเกณฑ์ส่งข้อความแนะนำ โดยตรวจสิทธิ์ผู้ส่งก่อน
- รหัส: [[20261014-02-peer-advice-chat|FR-10]], [[20261014-02-peer-advice-chat|FR-16]]
- บทบาทผู้ใช้: นักศึกษาผู้ส่ง
- ระดับความสำคัญ (MoSCoW): Must have

## 11. คิวรออนุมัติและการซ่อนข้อความจากผู้รับ
ข้อความทุกข้อความเข้าสถานะรออนุมัติ ผู้รับไม่เห็นข้อความที่ยังไม่อนุมัติหรือถูกปฏิเสธไม่ว่าทางใด
- รหัส: [[20261014-02-peer-advice-chat|FR-11]], [[20261014-02-peer-advice-chat|NFR-04]]
- บทบาทผู้ใช้: นักศึกษาผู้รับ, นักศึกษาผู้ส่ง
- ระดับความสำคัญ (MoSCoW): Must have

## 12. ตรวจ ระบุเชิงลบ และอนุมัติ/ปฏิเสธข้อความ
ผู้ตรวจระบุเชิงลบ/ไม่เชิงลบก่อนอนุมัติ อาจารย์และ admin สิทธิ์เท่ากัน ข้อความเชิงลบผู้ตรวจตัดสินเอง ไม่ปฏิเสธอัตโนมัติ
- รหัส: [[20261014-02-peer-advice-chat|FR-12]], [[20261014-02-peer-advice-chat|FR-13]], [[20261014-02-peer-advice-chat|FR-14]]
- บทบาทผู้ใช้: อาจารย์, Admin
- ระดับความสำคัญ (MoSCoW): Must have

## 13. ปฏิเสธพร้อมเหตุผลและแจ้งผู้ส่ง
การปฏิเสธต้องกรอกเหตุผล และผู้ส่งได้รับแจ้งพร้อมเหตุผล
- รหัส: [[20261014-02-peer-advice-chat|FR-15]]
- บทบาทผู้ใช้: อาจารย์, Admin, นักศึกษาผู้ส่ง
- ระดับความสำคัญ (MoSCoW): Must have

## 14. กันตรวจซ้ำระหว่างผู้ตรวจ
ข้อความที่ผู้ตรวจคนหนึ่งกำลังตรวจหรือตัดสินแล้วต้องไม่ถูกตัดสินซ้ำโดยอีกคน
- รหัส: [[20261014-02-peer-advice-chat|FR-18]]
- บทบาทผู้ใช้: อาจารย์, Admin
- ระดับความสำคัญ (MoSCoW): Should have

## 15. ประวัติการตรวจข้อความ (audit trail)
เก็บว่าใครตรวจ ผลที่ตัดสิน การระบุเชิงลบ/ไม่เชิงลบ และเหตุผล
- รหัส: [[20261014-02-peer-advice-chat|NFR-05]]
- บทบาทผู้ใช้: อาจารย์, Admin
- ระดับความสำคัญ (MoSCoW): Must have

## 16. AI ช่วยวิเคราะห์เชิงลบ/ไม่เชิงลบ
AI เสนอผลวิเคราะห์ให้ผู้ตรวจยืนยัน ผู้ตรวจตัดสินขั้นสุดท้าย (ไม่ใช้ AI ผู้ตรวจระบุเอง)
- รหัส: [[20261014-02-peer-advice-chat|FR-17]]
- บทบาทผู้ใช้: อาจารย์, Admin
- ระดับความสำคัญ (MoSCoW): Could have

## 17. การแสดงตัวตนผู้ส่งข้อความ
กำหนดว่าข้อความแสดงชื่อผู้ส่งหรือไม่ (ยังเป็นคำถามเปิดใน spec)
- รหัส: [[20261014-02-peer-advice-chat|NFR-06]]
- บทบาทผู้ใช้: นักศึกษาผู้ส่ง, นักศึกษาผู้รับ
- ระดับความสำคัญ (MoSCoW): Should have

## 18. จัดการซิงก์ล้มเหลว ป้ายข้อมูลไม่ทันสมัย และป้ายรอข้อมูล
เมื่อซิงก์จากระบบเดิมล้มเหลว (API ล่ม หมดเวลา ข้อมูลไม่ครบ/ผิดรูปแบบ) ระบบใช้ข้อมูลซิงก์ล่าสุดที่สำเร็จต่อ แจ้งผู้ดูแลระบบ และแสดงป้ายแก่ผู้เรียนว่าข้อมูลไม่ทันสมัยจนกว่าซิงก์สำเร็จ ถ้าเป็นการซิงก์ครั้งแรกที่ล้มเหลวและยังไม่เคยมีข้อมูลสำเร็จ ระบบไม่ประเมินความเสี่ยง แจ้งผู้ดูแลระบบ และผู้เรียนเห็นป้ายรอข้อมูล (ไม่แสดงผลประเมินใดๆ) ป้ายหายเมื่อซิงก์สำเร็จครั้งแรก ต่อยอดฟีเจอร์ 1
- รหัส: [[20261016-01-sync-failure-handling|FR-19]], [[20261016-03-first-sync-failure-and-expired-lock-decision|FR-23]]
- บทบาทผู้ใช้: ผู้ดูแลระบบ, ผู้เรียน
- ระดับความสำคัญ (MoSCoW): Should have

## 19. ห้องรวมแสดงข้อความที่อนุมัติแล้ว
ข้อความแนะนำถูกส่งเข้าห้องรวมเดียว เมื่ออนุมัติแล้วนักศึกษาทุกคนในระบบเห็นได้ (ไม่มีผู้รับรายคน/จับคู่) ข้อความที่ยังไม่อนุมัติหรือถูกปฏิเสธต้องไม่ปรากฏ ต่อยอดฟีเจอร์ 10-11
- รหัส: [[20261016-02-peer-chat-recipients-lock-resubmit|FR-20]], [[20261014-02-peer-advice-chat|NFR-04]]
- บทบาทผู้ใช้: นักศึกษาผู้ส่ง, นักศึกษาผู้รับ
- ระดับความสำคัญ (MoSCoW): Must have

## 20. ปลดล็อกข้อความที่ผู้ตรวจค้าง
เมื่อผู้ตรวจล็อกข้อความแล้วไม่ตัดสิน ระบบปลดล็อกอัตโนมัติเมื่อหมดเวลา (ค่าตั้งได้ ยังไม่กำหนดค่า) และอาจารย์หรือ Admin ปลดด้วยมือได้ ข้อความกลับเข้าคิวและไม่ถือเป็นการตัดสิน ต่อยอดฟีเจอร์ 14
- รหัส: [[20261016-02-peer-chat-recipients-lock-resubmit|FR-21]]
- บทบาทผู้ใช้: Admin, อาจารย์
- ระดับความสำคัญ (MoSCoW): Should have

## 21. ส่งข้อความใหม่หลังถูกปฏิเสธ
ข้อความที่ถูกปฏิเสธปิดถาวร แก้ไม่ได้ ผู้ส่งสร้างข้อความใหม่ได้ ซึ่งต้องผ่านการตรวจใหม่ทั้งหมด และ audit trail เก็บความสัมพันธ์ข้อความเดิม-ใหม่ (ต่อยอดฟีเจอร์ 13 และ 15, NFR-05)
- รหัส: [[20261016-02-peer-chat-recipients-lock-resubmit|FR-22]]
- บทบาทผู้ใช้: นักศึกษาผู้ส่ง, อาจารย์, Admin
- ระดับความสำคัญ (MoSCoW): Should have

## 22. ปฏิเสธคำตัดสินเมื่อผู้ตัดสินไม่ได้ถือล็อกที่ยังใช้ได้
เมื่อผู้ตรวจกดตัดสินโดยไม่ได้ถือล็อกที่ยังใช้ได้ ไม่ว่าสาเหตุใด ระบบปฏิเสธคำตัดสินนั้น (ไม่บันทึกเป็นการตัดสิน) แจ้งผู้ตรวจ และข้อความอยู่ในคิวรออนุมัติ ไม่หลุดเป็นอนุมัติโดยไม่ผ่านการตรวจที่ถูกต้อง (สอดคล้อง NFR-04, NFR-05) ครอบคลุมอย่างน้อย (ก) ล็อกถูกปลดอัตโนมัติเมื่อหมดเวลา (ข) ล็อกถูกอาจารย์/Admin ปลดด้วยมือ (ฟีเจอร์ 20) แล้วผู้ตรวจเดิมกดตัดสินภายหลัง (ค) ผู้ตรวจอื่นล็อกข้อความต่อแล้ว ต่อยอดฟีเจอร์ 14 และ 20 (ระดับ "สูง" ยังรอผู้ใช้ยืนยัน)
- รหัส: [[20261016-03-first-sync-failure-and-expired-lock-decision|FR-24]]
- บทบาทผู้ใช้: อาจารย์, Admin
- ระดับความสำคัญ (MoSCoW): Must have
