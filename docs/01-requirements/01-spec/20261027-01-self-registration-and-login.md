# การสมัครเอง (self-registration) และการล็อกอิน

- ID: REQ-20261027-01 | วันที่: 2026-10-27 | สถานะ: Draft
- ดู [[../backlog|Backlog]]
- ส่วนเสริมของ [[20261017-01-user-role-advisor-eligibility-management]] (FR-25, NFR-07) และเกี่ยวข้องกับ [[20261014-01-student-risk-alert]] (NFR-01) และ [[20261014-02-peer-advice-chat]] (NFR-04, NFR-05)

## 1. ที่มา / Requirement ดิบ
มาจากงานรายวิชา ส่วน C: ล็อกอิน (สมัคร, เข้าสู่ระบบ, ออกจากระบบ, ไม่ล็อกอินให้เด้งไปหน้า login, รายการใหม่บันทึก uid ของผู้ทำ) ผู้ใช้ตัดสินใจแล้วให้ระบุที่มานี้

ผู้ใช้สมัครบัญชีด้วยอีเมล/รหัสผ่านได้ด้วยตนเอง แล้วระบบสร้างบัญชีผู้ใช้ให้อัตโนมัติด้วยบทบาท นักศึกษา (student) เท่านั้น สถานะใช้งาน ผู้สมัครเลือกบทบาทเองไม่ได้ และห้ามเขียนทับบัญชีผู้ใช้ที่มีอยู่แล้วของ uid เดียวกัน หลังเข้าสู่ระบบระบบพาไปหน้าตามบทบาท ทุกหน้ามีปุ่มออกจากระบบ ผู้ที่ยังไม่ล็อกอินถูกพาไปหน้า login และรายการที่สร้างใหม่บันทึก uid ของผู้สร้าง

## 2. เป้าหมาย
- ให้ผู้ใช้เริ่มใช้ระบบได้เองโดยไม่ต้องรอ Admin สร้างบัญชี โดยไม่เปิดช่องให้ยกระดับสิทธิ์ตัวเอง
- ให้แต่ละบทบาทเข้าหน้าที่เหมาะสมหลังเข้าสู่ระบบ และหน้าภายในเข้าถึงได้เฉพาะผู้ที่ยืนยันตัวตนแล้ว
- ให้ทุกรายการที่สร้างใหม่ตรวจสอบย้อนหลังได้ว่าใครเป็นผู้ทำ

## 3. ผู้ใช้ / บทบาทที่เกี่ยวข้อง
- ผู้สมัครใหม่ (กลายเป็นนักศึกษา), ผู้ใช้ทุกบทบาท (เข้าสู่ระบบ/ออกจากระบบ), Admin (ยังเป็นผู้เดียวที่เพิ่มบทบาทอื่นให้บัญชีได้ตาม FR-25)

## 4. Functional Requirements

| รหัส | ความต้องการ | รายละเอียด | ระดับความสำคัญ |
|------|-------------|------------|----------------|
| FR-28 | สมัครบัญชีด้วยตนเอง | ผู้ใช้สมัครด้วยอีเมลและรหัสผ่านได้ เมื่อสมัครสำเร็จระบบสร้างบัญชีผู้ใช้ให้อัตโนมัติด้วยบทบาท นักศึกษา (student) เพียงบทบาทเดียวและสถานะใช้งาน ผู้สมัครเลือกหรือส่งบทบาทเองไม่ได้ (ค่าที่ผู้สมัครส่งมาเรื่องบทบาทถูกเพิกเฉย) และถ้ามีบัญชีผู้ใช้ของ uid นั้นอยู่แล้ว ห้ามเขียนทับ (รวมบัญชีที่มาจากการนำเข้าหรือที่ Admin สร้าง) การสร้างบัญชีทำโดยฝั่งระบบ ไม่ใช่การเขียนตรงจากหน้าเว็บ | กลาง |
| FR-29 | เข้าสู่ระบบและพาไปหน้าตามบทบาท | ผู้ใช้เข้าสู่ระบบด้วยอีเมล/รหัสผ่าน ระบบบอกบทบาทและสถานะของตนเองให้หน้าเว็บทราบ (อ่านอย่างเดียว เฉพาะข้อมูลของตนเอง) แล้วพาไปหน้า: Admin → หน้า Admin, อาจารย์ (ผู้ตรวจ) → หน้าผู้ตรวจ, บทบาทอื่นรวมนักศึกษาและครู/อาจารย์ที่ปรึกษา → แดชบอร์ด ถ้ามีหลายบทบาทใช้ลำดับ Admin → อาจารย์ → อื่นๆ บัญชีที่ปิดการใช้งานเข้าใช้งานไม่ได้ | กลาง |
| FR-30 | ออกจากระบบและบังคับล็อกอิน | ทุกหน้ามีปุ่มออกจากระบบ เมื่อกดแล้วสิ้นสุดเซสชันและกลับหน้า login ผู้ที่ยังไม่ล็อกอินที่เข้าหน้าใดๆ ที่ต้องยืนยันตัวตนถูกพาไปหน้า login | กลาง |
| FR-31 | บันทึกผู้สร้างรายการ | ทุกรายการที่สร้างใหม่บันทึก uid ของผู้สร้างที่ยืนยันตัวตนแล้ว (ข้อความแชทมี senderId อยู่แล้วและถือว่าเข้าข้อกำหนดนี้) uid มาจากตัวตนที่ยืนยันแล้วของผู้เรียกเท่านั้น ไม่รับจากค่าที่ผู้ใช้ส่งมา | กลาง |

> ระดับความสำคัญของ FR-28..31 ผู้ใช้ยืนยันแล้วเมื่อ 2026-10-28 (ระดับ กลาง ตามข้อเสนอเดิม)

## 5. Non-functional Requirements
ไม่เพิ่มรหัส NFR ใหม่ ใช้ NFR-07 เดิม (audit trail) โดยขยายให้ครอบคลุม "การสมัครเอง" ดูหัวข้อ 6 และการแก้ [[20261017-01-user-role-advisor-eligibility-management]]

## 6. Business Rules
- ผู้สมัครเองได้บทบาท student เท่านั้น บทบาทอื่น (ครู/อาจารย์ที่ปรึกษา, อาจารย์, Admin) กำหนดโดย Admin ตาม FR-25 หรือมาจากการนำเข้า
- ห้ามเขียนทับบัญชีผู้ใช้ที่มีอยู่แล้วของ uid เดียวกันไม่ว่ากรณีใด
- การสมัครเองต้องบันทึก audit trail ตาม NFR-07 (ผู้ทำ = uid ผู้สมัคร, เวลา, ค่าที่สร้าง: บทบาท student สถานะใช้งาน, แหล่งที่มา = สมัครเอง)
- นักศึกษาที่สมัครเองยังต้องผ่านเกณฑ์ตาม FR-27 จึงจะส่งข้อความได้ (FR-16) การสมัครไม่ให้สิทธิ์เพิ่ม
- สิทธิ์ที่ขึ้นกับบทบาทตัดสินจากข้อมูลบทบาทในระบบนี้เท่านั้น ไม่ใช่จากสิ่งที่หน้าเว็บส่งมา

## 7. ขอบเขต
- In scope: สมัครด้วยอีเมล/รหัสผ่าน, เข้าสู่ระบบ, ออกจากระบบ, พาไปหน้าตามบทบาท, บังคับล็อกอิน, บันทึก uid ผู้สร้างรายการ, audit การสมัครเอง
- Out of scope (assumption): การยืนยันอีเมล, การรีเซ็ต/เปลี่ยนรหัสผ่าน, ล็อกอินผ่านผู้ให้บริการภายนอก, การป้องกันการสมัครซ้ำ/บอตเพิ่มเติม, การผูกบัญชีที่สมัครเองกับผู้เรียนที่นำเข้าจากระบบเดิมที่อีเมลตรงกัน (ยังไม่กำหนด)

## 8. Acceptance Criteria
- AC-1 (FR-28): สมัครด้วยอีเมล/รหัสผ่านสำเร็จแล้วมีบัญชีผู้ใช้บทบาท student สถานะใช้งานเพียงบทบาทเดียว
- AC-2 (FR-28): ผู้สมัครที่พยายามส่งบทบาทอื่น (เช่น admin) ได้บทบาท student เท่านั้น
- AC-3 (FR-28): uid ที่มีบัญชีอยู่แล้ว สมัครซ้ำ/เรียกสร้างซ้ำแล้วข้อมูลเดิม (บทบาท สถานะ) ไม่ถูกเปลี่ยน
- AC-4 (FR-28, NFR-07): การสมัครเองมีบันทึก audit ผู้ทำ เวลา และค่าที่สร้าง
- AC-5 (FR-29): หลังเข้าสู่ระบบ admin ไปหน้า Admin, อาจารย์ไปหน้าผู้ตรวจ, นักศึกษาและครู/อาจารย์ที่ปรึกษาไปแดชบอร์ด; ผู้มีหลายบทบาทไปตามลำดับ Admin → อาจารย์ → อื่นๆ
- AC-6 (FR-29): บัญชีที่ปิดการใช้งานเข้าใช้งานไม่ได้
- AC-7 (FR-30): ทุกหน้ามีปุ่มออกจากระบบ และหลังออกจากระบบเข้าหน้าภายในแล้วถูกพาไปหน้า login
- AC-8 (FR-30): ผู้ที่ยังไม่ล็อกอินเข้าหน้า Admin/ผู้ตรวจ/แดชบอร์ดโดยตรงถูกพาไปหน้า login
- AC-9 (FR-31): รายการที่สร้างใหม่มี uid ผู้สร้างตรงกับผู้เรียก และไม่สามารถระบุ uid อื่นแทนได้

## 9. Assumptions และคำตอบที่ได้จากผู้ใช้
คำตอบ/การตัดสินใจจากผู้ใช้ (2026-10-27):
- ที่มา = งานรายวิชา ส่วน C: ล็อกอิน
- ผู้สมัครเองได้เฉพาะบทบาท student สถานะใช้งาน เลือกบทบาทเองไม่ได้ ห้ามเขียนทับบัญชีที่มีอยู่
- หน้าเว็บทราบบทบาทหลังล็อกอินผ่านการอ่านโปรไฟล์ของตนเองแบบอ่านอย่างเดียว (callable `getMyProfile` คืน name/roles/status) เพราะหน้าเว็บอ่านข้อมูลผู้ใช้ตรงไม่ได้ และหน้าเว็บห้ามเขียนข้อมูลผู้ใช้ตรง (ระบุไว้เป็นการตัดสินใจเชิงออกแบบ รายละเอียดอยู่ใน technical spec)
- ให้แก้ข้อ Out of scope ของ REQ-20261017-01 และ FR-25 ให้สอดคล้อง (ทำแล้ว)
- เอกสาร spec ไม่ผูก technology (technology ที่ตัดสินใจแล้วอยู่ใน `docs/02-design/02-technical/technology-stack.md`)
- ระดับความสำคัญ กลาง: ผู้ใช้ยืนยันแล้วเมื่อ 2026-10-28
- ไม่ได้ถามคำถามเพิ่มเติมกับผู้ใช้ เพราะผู้ใช้ระบุประเด็นหลักไว้ครบและสั่งว่าอย่าถามซ้ำ
