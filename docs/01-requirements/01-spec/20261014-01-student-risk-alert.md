# ระบบติดตามสถานการณ์การเรียนและแจ้งเตือนความเสี่ยง

- ID: REQ-20261014-01 | วันที่: 2026-10-14 | สถานะ: Draft
- ดู [[../backlog|Backlog]]

## 1. ที่มา / Requirement ดิบ
ระบบที่ช่วยติดตามสถานการณ์การเรียนของนักเรียน/นักศึกษา โดยพิจารณาจากหลายตัวแปรร่วมกัน (เกรด/ผลการเรียน, การเข้าเรียน, การส่งงาน, แนวโน้มผลการเรียน) แล้วแจ้งเตือนผู้เรียนเมื่อเข้าเงื่อนไขที่มีความเสี่ยง พร้อมให้คำแนะนำแนวทางการเรียนที่คำนวณเฉพาะบุคคลจากข้อมูลย้อนหลังของผู้เรียนแต่ละคน

## 2. เป้าหมาย
- ให้ผู้เรียนและครูที่ปรึกษาเห็นสถานการณ์การเรียนจากหลายตัวแปรร่วมกัน
- ตรวจพบความเสี่ยงตั้งแต่เนิ่น ๆ และแจ้งเตือนทันเวลา
- ให้คำแนะนำแนวทางการเรียนที่เฉพาะบุคคล คำนวณจากข้อมูลย้อนหลังของผู้เรียนแต่ละคน

## 3. ผู้ใช้ / บทบาท
- ผู้เรียน: ดูสถานการณ์การเรียนของตน รับแจ้งเตือน และรับคำแนะนำ
- ครู/อาจารย์ที่ปรึกษา: ดูสถานการณ์และการแจ้งเตือนของผู้เรียนในที่ปรึกษา
- ผู้ดูแลระบบ (assumption): ตั้งค่า threshold และการเชื่อมต่อระบบภายนอก

## 4. Functional Requirements

| รหัส | ความต้องการ | รายละเอียด | ระดับความสำคัญ |
|------|-------------|------------|----------------|
| FR-01 | ดึงข้อมูลจากระบบเดิม | ดึงข้อมูลเกรด/ผลการเรียน การเข้าเรียน และการส่งงาน จากระบบเดิม (LMS/ระบบทะเบียน) ผ่าน API | สูง |
| FR-02 | คำนวณแนวโน้มผลการเรียน | คำนวณแนวโน้มผลการเรียนของผู้เรียนจากข้อมูลย้อนหลัง | สูง |
| FR-03 | ประเมินความเสี่ยงหลายตัวแปร | ประเมินความเสี่ยงของผู้เรียนจากหลายตัวแปรร่วมกัน ด้วยกฎ threshold ที่ปรับค่าได้ | สูง |
| FR-04 | แจ้งเตือนความเสี่ยง | แจ้งเตือนผู้เรียนเมื่อเข้าเงื่อนไขเสี่ยง ผ่านระบบ (in-app) และอีเมล | สูง |
| FR-05 | คำแนะนำเฉพาะบุคคล | สร้างคำแนะนำแนวทางการเรียนเฉพาะบุคคลจากข้อมูลย้อนหลังของผู้เรียนแต่ละคน | สูง |
| FR-06 | แดชบอร์ดผู้เรียน | แดชบอร์ดสถานการณ์การเรียนสำหรับผู้เรียน | กลาง |
| FR-07 | มุมมองครู/อาจารย์ที่ปรึกษา | ครู/อาจารย์ที่ปรึกษาดูสถานการณ์และการแจ้งเตือนของผู้เรียนในความดูแล | กลาง |
| FR-08 | ตั้งค่า threshold | ผู้ดูแลระบบตั้งค่า threshold ของกฎความเสี่ยงได้ | สูง |
| FR-09 | ประวัติการแจ้งเตือนและคำแนะนำ | เก็บประวัติการแจ้งเตือนและคำแนะนำ | ต่ำ |

> การแปลงรหัส/ระดับจากต้นฉบับ: FR-1..FR-9 → FR-01..FR-09; Must → สูง, Should → กลาง, Could → ต่ำ

## 5. Non-functional Requirements

| รหัส | ด้าน | ความต้องการ |
|------|------|-------------|
| NFR-01 | ความเป็นส่วนตัว | ข้อมูลผลการเรียนเป็นข้อมูลส่วนบุคคล ผู้เรียนเห็นเฉพาะข้อมูลตน ครูเห็นเฉพาะผู้เรียนในความดูแล (ต้องยืนยันนโยบายตาม PDPA) — ระดับความสำคัญ: สูง |
| NFR-02 | ความสามารถอธิบายได้ | การแจ้งเตือนต้องบอกเหตุผลว่าเข้าเงื่อนไขใด — ระดับความสำคัญ: สูง |
| NFR-03 | ความทันสมัยของข้อมูล | ความถี่การซิงก์ข้อมูลยังไม่กำหนด (ดูข้อ 10) — ระดับความสำคัญ: กลาง |

> ระดับความสำคัญของ NFR-01..03 เป็นข้อเสนอของผู้นำเข้า (ต้นฉบับไม่ได้ระบุ) รอผู้ใช้ยืนยัน

## 6. Business Rules
- ความเสี่ยงประเมินจาก 4 ตัวแปร: เกรด/ผลการเรียน, การเข้าเรียน, การส่งงาน, แนวโน้มผลการเรียน
- เงื่อนไขความเสี่ยงเป็นกฎ threshold ปรับค่าได้ เช่น เข้าเรียนต่ำกว่า X% หรือเกรดลดลงต่อเนื่อง N ครั้ง (ค่าตัวอย่าง ยังไม่ได้กำหนดจริง)
- คำแนะนำต้องอิงข้อมูลย้อนหลังของผู้เรียนคนนั้น ไม่ใช่คำแนะนำทั่วไป

## 7. ขอบเขต
- In scope: เชื่อมข้อมูลผ่าน API, ประเมินความเสี่ยงด้วยกฎ threshold, แจ้งเตือนผู้เรียนทาง in-app และอีเมล, คำแนะนำเฉพาะบุคคล, มุมมองสำหรับผู้เรียนและครูที่ปรึกษา
- Out of scope: โมเดล ML ทำนายความเสี่ยง, แจ้งเตือนผ่าน LINE/Push, การบันทึกข้อมูลเกรด/เข้าเรียนเองในระบบนี้, การแจ้งผู้ปกครอง (assumption ยืนยันภายหลังได้)

## 8. Acceptance Criteria
- AC-1: เมื่อข้อมูลของผู้เรียนเข้าเงื่อนไขเสี่ยงตามกฎที่ตั้งไว้ ผู้เรียนได้รับแจ้งเตือนทั้งใน-app และอีเมล พร้อมเหตุผล
- AC-2: เมื่อผู้ดูแลระบบเปลี่ยนค่า threshold การประเมินรอบถัดไปใช้ค่าใหม่
- AC-3: ผู้เรียนแต่ละคนได้คำแนะนำที่ต่างกันตามข้อมูลย้อนหลังของตน
- AC-4: ผู้เรียนเห็นเฉพาะข้อมูลของตน ครูที่ปรึกษาเห็นเฉพาะผู้เรียนในความดูแล
- AC-5: ข้อมูลจาก LMS/ระบบทะเบียนถูกดึงผ่าน API และสะท้อนในการประเมินความเสี่ยง

## 9. Assumptions และคำตอบจากผู้ใช้
คำตอบจากผู้ใช้: แหล่งข้อมูล = เชื่อมระบบเดิม (LMS/ระบบทะเบียน) ผ่าน API; บทบาท = ผู้เรียน + ครู/อาจารย์ที่ปรึกษา; เงื่อนไขความเสี่ยง = กฎ threshold ปรับค่าได้; ช่องทางแจ้งเตือน = In-app + อีเมล

Assumptions: มีบทบาทผู้ดูแลระบบ; "คำแนะนำเฉพาะบุคคล" สร้างด้วยกฎ/สถิติจากข้อมูลย้อนหลัง (ไม่ใช้ ML ในเฟสนี้); ผู้เรียนต้องมีข้อมูลย้อนหลังเพียงพอจึงจะคำนวณแนวโน้มและคำแนะนำได้ (ผู้เรียนใหม่ใช้เฉพาะกฎพื้นฐาน)

## 10. คำถามที่ยังเปิดอยู่
- ระบบเดิมคือระบบใด (LMS/ทะเบียนยี่ห้อไหน) และมี API พร้อมใช้หรือไม่
- ระดับผู้เรียน: ประถม/มัธยม/มหาวิทยาลัย (มีผลต่อเกณฑ์และการแจ้งผู้ปกครอง)
- ค่า threshold เริ่มต้นของแต่ละตัวแปร และความถี่ในการประเมิน/ซิงก์ข้อมูล
- ครูที่ปรึกษาได้รับแจ้งเตือนด้วยหรือไม่ หรือดูในแดชบอร์ดเท่านั้น
- นโยบายความเป็นส่วนตัว/PDPA และระยะเวลาเก็บข้อมูล
