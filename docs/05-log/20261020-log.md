## ปุ่มอนุมัติ/ปฏิเสธ/ล็อกในหน้า review-queue (ผ่าน emulator)
- สาขา `claude/review-buttons` (PR #19 merge แล้ว) เขียน `web/review-queue/` ใหม่: ล็อกเพื่อตรวจ, เลือกเชิงลบ/ไม่เชิงลบ, อนุมัติ, ปฏิเสธ (ต้องมีเหตุผล), ปลดล็อก, ล็อกใหม่เพื่อตรวจต่อหลังรีโหลด เรียก callable ผ่าน Auth + Functions emulator (`#emulator`) ไม่แตะ Firestore ตรง
- Backend: `listReviewQueue` คืนข้อความที่ผู้เรียกล็อกอยู่ (flag `lockedByMe`, ไม่มี token) เพื่อให้ผู้ตรวจหาเจออีกครั้ง เพิ่ม test (36 ข้อผ่าน)
- เพิ่ม `functions/scripts/seed-emulator.js` (ปฏิเสธรันถ้าไม่ได้ชี้ emulator) และ Auth emulator ใน `firebase.json`
- ทดสอบมือในเบราว์เซอร์กับ emulator: login ผู้ตรวจ, ล็อก, ปฏิเสธโดยไม่เลือก/ไม่ใส่เหตุผลขึ้น error และคงค่าที่กรอก, ปฏิเสธมีเหตุผล (msg-c) และอนุมัติ (msg-b) หายจากคิว, ตรวจ Firestore emulator ว่า decision/audit/แจ้งเตือนผู้ส่งถูกบันทึก, รีโหลดแล้วล็อกใหม่และปลดล็อก (audit `unlock_manual`)
- พบและแก้ระหว่างทดสอบ: (1) `functions/index.js` ที่ merge ใน PR #19 ไม่ได้ export callable ของ chat (test เรียก handler ตรงจึงไม่เจอ) (2) `engines.node` ต้องเป็น 22 (3) `serve` ตัด `?emulator=1` จึงใช้ `#emulator` (4) error จากการกรอกไม่ครบทำให้หน้า re-render ล้างค่าที่กรอก แก้ให้แสดง error ในที่

- ค้าง: deploy จริง (ต้อง Blaze), T-3-15, ย้าย `lock` ออกจากเอกสารที่ reviewer อ่านตรงได้, ยังไม่ได้ทดสอบด้วยบัญชี admin และกรณีผู้ตรวจ 2 คนชนกันในหน้าเว็บ (ครอบคลุมใน test backend แล้ว)
